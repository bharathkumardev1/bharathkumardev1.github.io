# bharathkumardev1.github.io

My site, at https://bharathkumardev1.github.io. One HTML page, one stylesheet and four
small ES modules, with no framework and no build step for the page itself. Two demos run
in the browser on data exported from my project repos:

- **Filing search** ([`assets/finrag.mjs`](assets/finrag.mjs)): the filter, BM25 and
  statement routing from [finance-rag-eval](https://github.com/bharathkumardev1/finance-rag-eval)
  over the 84 SEC filings that FinanceBench questions cite, one gzipped filing at a time.
- **Readmission call list** ([`assets/gbdt.mjs`](assets/gbdt.mjs)): the LightGBM trees,
  calibration and held-out capacity curves from
  [readmission-capacity](https://github.com/bharathkumardev1/readmission-capacity).

## Where the numbers come from

The results tables and the sentences around them are generated by
[`tools/build.mjs`](tools/build.mjs) from `data/finrag/summary.json`, which
`finrag export-demo` writes from that repo's `results/eval.json`. The build also asserts
each claim in the prose (for example, that the hybrid's gain over BM25 is inside its
interval), so a rerun that changes a conclusion fails the build instead of leaving a
wrong sentence on the page.

```bash
# in finance-rag-eval
finrag export-demo --out ../bharathkumardev1.github.io/data/finrag   # then move parity.json to tests/
# in readmission-capacity
readmit export --out ../bharathkumardev1.github.io/data/readmit      # then trim parity.json into tests/readmit_parity.json

# here
npm run build    # regenerate the marked sections of index.html
npm test         # Node 20+, no dependencies
```

## Tests

`npm test` checks that `index.html` matches the summary, that every number in the results
table comes from it, that the JS search returns the same pages with the same float32
scores as the Python pipeline on 438 question and setting pairs, that the JS tree walker
matches LightGBM on 300 held-out rows, that the readmission figures in the prose come out
of the shipped rankings, that local links resolve, and that the page stays under 120 KB
before the demos load. CI runs the same on every push.
